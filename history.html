Version history

A hand-made tool, updated by hand. When something breaks, it goes on this page. Newest first. (The changelog generator is a tool — this page is just the site's own diary.)

v3.0 — 2026-09-05 the systemd toolbox release

Added

  • Four systemd tools, one shared parsing engine: a .service generator (with a status=203/EXEC guardrail), a two-way cron ↔ timer converter that warns when the grammars genuinely disagree, a line-numbered unit checker, and an OnCalendar editor that previews the next five fire times.
  • The engine ships with its own test suite (84 checks) and the site deploys through GitHub — tests run before anything goes live.

Changed

  • The homepage is a toolbox now: unit tools join the commit four, one page each, nothing uploaded — the site grew from "one knife" to "one shelf".

v2.5 — 2026-09-05 the "one page, one job" release

Changed

  • The homepage does one thing now: generate commit messages. Squash, changelog and lint moved to their own pages — same engine, one job per page, easier to link to.
  • A resources shelf appeared in the nav. It's the list of specs and free tools we actually use while building this site.

Unchanged

  • The engine, the tests, and the promise: nothing leaves your tab.

v2.4 — 2026-09-05 the "usable by the person who built it" release

Added

  • Machine-translation shield. The UI is now translate="no". Browser auto-translate had been renaming "Squash" to the sport and "Lint" to fabric fuzz. No third machine in the loop.
  • Wider desktop layout (1000/1180px). The old 880px reading measure made the tool feel like a bookmarklet on a real monitor.

v2.3 — 2026-09-05 the "where would I actually use this" release

Added

  • Squash & PR titles. Paste git log --oneline from a feature branch, get one title that leads with the dominant type, plus a ready body listing every commit — for the squash box on GitHub's web UI.
  • Changelog drafts. Same log in, grouped markdown out — Features, Bug Fixes, Performance, the lot. A first line like v1.4.0 becomes the header, breaking changes get the ⚠️.
  • Commit lint. Paste one message, get its spec violations listed — past tense, capital start, trailing period, the usual suspects — with a corrected version to copy.

The honest part

All three exist because someone asked the only question that matters: "I really don't know where this simple thing would be useful?" Fair. The diff box was never the whole job — squash merges, changelogs and reviews were always the other half of it.

v2.2 — 2026-09-05 the alignment incident

Fixed

  • The FAQ and history sections had drifted to the left edge of the page. Cause: a CSS margin shorthand quietly overwriting the auto-centering it shared with the layout wrapper. It looked intentional for a while. It was not.

Changed

  • Output redesigned as a dark terminal panel with the format switch inside it — easier to find, harder to mistake for decoration.

v2.1 — 2026-09-05 rules that actually read the diff

Added

  • Signal mining: error messages thrown in the diff become subjects; new guards, new exports, lockfile bumps and deletions each steer the type.
  • Three variants per generation, each with a one-line why.

v2.0 — 2026-09-02 the rewrite

Added

  • Style learner: paste git log --pretty=format:%s -20 and the generator picks up your types, scope habits, median length and emoji use. Stored in your browser, wiped with one click.

Unchanged

  • Nothing leaves the tab. That part was right the first time.

v1.0 — 2026-09-02 first commit

  • One box, one output. It worked. It was a little generic, and it knew it — which is why v2 exists.
