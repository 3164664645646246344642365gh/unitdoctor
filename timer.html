    Where the two grammars genuinely disagree
    
    
      
      
    1. Day-of-month + day-of-week. cron fires when either matches
      (if both are restricted); systemd fires only when both match. The converter keeps
      the AND and tells you to split into two OnCalendar= lines for cron's OR.
      2. 
      
    2. @reboot. cron's "once at boot" has no OnCalendar equivalent — the right
      idiom is OnBootSec=1min in the [Timer] section, which is what the error will
      suggest.
      3. 
      
    3. Seconds. OnCalendar can fire sub-minute; cron cannot. Going OnCalendar
      → cron with seconds warns that precision will be lost.
      4. 
      
    4. Persistent=true is added by default: a job missed while the box was off
      runs once at next boot, which cron silently skips.
      5. 
    
    
  
    

  
    
    
    Quick questions
    
    
    
      How do I install the .timer file?
      
    Save it as /etc/systemd/system/my-task.timer, pair it with a .service that
      has the same base name (or generate both with our unit generator),
      then sudo systemctl daemon-reload && sudo systemctl enable --now my-task.timer.
      Enable the timer, not the service.
    
    
    
    
    
      How do I verify the schedule on my server?
      
    systemd-analyze calendar 'YOUR-EXPRESSION' prints the next fires straight
      from systemd — it is the final authority. The preview below uses the same rules in
      JavaScript, in your browser's timezone.
    
    
    
    
    
      Is my crontab uploaded?
      
    No. Everything — parsing, conversion, the fire-time preview — runs in your tab.
